# 通用项目统计服务 - 集成指南

## 📦 组件说明

这是一个**完全解耦、可复用**的项目统计解决方案，包含：

1. **服务层** (`services/base_project_stats_service.py`)
   - `BaseProjectStatsService` - 基础统计服务
   - `AdvancedProjectStatsService` - 高级统计服务（扩展版）

2. **路由层** (`routers/base_project_stats_router.py`)
   - 提供 RESTful API 接口
   - 自动 Swagger 文档
   - 统一错误处理

---

## 🚀 快速集成（3 步）

### 第一步：复制文件

将以下两个文件复制到你的项目：

```bash
# 服务层
cp services/base_project_stats_service.py /你的项目/services/

# 路由层  
cp routers/base_project_stats_router.py /你的项目/routers/
```

### 第二步：注册路由

在你的 FastAPI 主入口文件中添加：

```python
from fastapi import FastAPI
from routers.base_project_stats_router import router as stats_router

app = FastAPI()

# 注册统计路由
app.include_router(stats_router, prefix="/v1", tags=["项目统计"])
```

### 第三步：配置数据库连接

确保你的项目有数据库连接模块，并修改服务层中的导入：

```python
# 在 base_project_stats_service.py 中修改
from your_project.database import execute_query  # 替换原来的导入
```

完成！现在你可以访问：`http://your-api.com/v1/stats/project/basic`

## 📊 API 接口列表

### 1. 基础统计接口

**URL**: `GET /v1/stats/project/basic`

**返回示例**:
```json
{
  "success": true,
  "data": {
    "total_projects": 150,
    "not_started_projects": 30,
    "ongoing_projects": 95,
    "completed_projects": 25
  },
  "timestamp": "2024-03-20T10:30:00"
}
```

**业务逻辑**:
- **未开始**: 当前日期 < 计划开始日期
- **已结项**: 实际结束日期存在且 < 当前日期
- **进行中**: 总数 - 未开始 - 已结项

---

### 2. 高级统计接口

**URL**: `GET /v1/stats/project/advanced`

**返回示例**:
```json
{
  "success": true,
  "data": {
    "basic": { ... },  // 基础统计
    "by_month": [
      {"month": "2024-03", "count": 15},
      {"month": "2024-02", "count": 12}
    ],
    "by_manager": [
      {"manager": "张三", "count": 8},
      {"manager": "李四", "count": 5}
    ],
    "delayed_projects": {
      "count": 3,
      "projects": [...]
    }
  }
}
```

---

### 3. 项目分类接口

**URL**: `POST /v1/stats/project/categorize`

**请求体**:
```json
[
  {
    "project_id": 1,
    "planned_start_date": "2024-01-01",
    "actual_end_date": null
  }
]
```

**返回**:
```json
{
  "success": true,
  "data": [
    {
      "project_id": 1,
      "category": "进行中"
    }
  ],
  "count": 1
}
```

### 方式二：重写判定逻辑

```python
class CustomProjectStatsService(BaseProjectStatsService):
    
    @classmethod
    def categorize_project(cls, project_data: Dict) -> str:
        """
        自定义项目分类逻辑
        
        例如：添加"已延期"状态
        """
        current_date = datetime.now().date()
        
        planned_end = project_data.get(cls.FIELD_MAPPING['planned_end'])
        actual_end = project_data.get(cls.FIELD_MAPPING['actual_end'])
        
        # 检查是否延期
        if planned_end and current_date > planned_end and not actual_end:
            return "已延期"
        
        # 调用父类逻辑处理其他情况
        return super().categorize_project(project_data)
```

```vue
<!-- ProjectStats.vue -->
<template>

      <el-col :span="6" v-for="stat in statsList" :key="stat.key">

import { ref, onMounted } from 'vue'
import axios from 'axios'

const stats = ref({
  total_projects: 0,
  not_started_projects: 0,
  ongoing_projects: 0,
  completed_projects: 0

// 卡片配置
const statsList = ref([
  { key: 'total_projects', title: '总项目数', gradient: 'linear-gradient(135deg, #667eea 0%, #764ba2 100%)', value: 0 },
  { key: 'not_started_projects', title: '未开始', gradient: 'linear-gradient(135deg, #f093fb 0%, #f5576c 100%)', value: 0 },

  { key: 'completed_projects', title: '已结项', gradient: 'linear-gradient(135deg, #43e97b 0%, #38f9d7 100%)', value: 0 }
])

// 获取统计数据
const fetchStats = async () => {
  try {
    const response = await axios.get('/v1/stats/project/basic')
    stats.value = response.data.data
    
    // 更新卡片数值

    console.error('获取统计数据失败:', error)
  }
}

onMounted(() => {
  fetchStats()
})
</script>
```

## 🗄️ 数据库要求

### 必需表结构

```sql
CREATE TABLE projects (
    project_id INT PRIMARY KEY AUTO_INCREMENT,
    project_name VARCHAR(255),
    planned_start_date DATE,      -- 必需
    planned_end_date DATE,        -- 推荐
    actual_start_date DATE,       -- 推荐
    actual_end_date DATE,         -- 必需（用于已结项判定）
    project_manager VARCHAR(100), -- 可选（用于负责人统计）
    project_status VARCHAR(50),   -- 可选
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

### 最小化版本

如果只需要基础统计，最少需要这两个字段：
- `planned_start_date` (DATE)
- `actual_end_date` (DATE)

## 🐛 常见问题

### Q1: 如何修改状态判定逻辑？
**A**: 继承 `BaseProjectStatsService`，重写 `_count_not_started()` 或 `categorize_project()` 方法。

### Q2: 表名或字段名不同怎么办？
**A**: 修改 `TABLE_NAME` 和 `FIELD_MAPPING` 类属性，或重写相关方法。

### Q3: 如何添加新的统计维度？
**A**: 参考 `AdvancedProjectStatsService`，添加新的统计方法并在 `get_advanced_statistics()` 中调用。

### Q4: 如何处理时区问题？
**A**: 在服务层统一使用 UTC 时间，或在配置中设置时区：
```python
import pytz
TIMEZONE = pytz.timezone('Asia/Shanghai')
```

### Q5: 性能优化建议？
**A**: 
1. 为日期字段添加索引
2. 使用缓存（Redis/Memcached）
3. 定期预计算统计数据
4. 分页查询大量数据

### 1. 添加缓存层

```python
from functools import lru_cache
import time

class CachedProjectStatsService(BaseProjectStatsService):
    
    @classmethod
    @lru_cache(maxsize=1)
    def get_project_statistics(cls) -> Dict:
        """带缓存的统计方法（缓存 5 分钟）"""
        result = super().get_project_statistics()
        # 5 分钟后自动过期
        cache_time = time.time()
        return {**result, '_cache_time': cache_time}
```
